Contribute

Submit a new bound

Improved an upper bound, proved a better lower bound or closed an instance? Tell us, and we will check it and credit you on this site.

What to send

New upper bound

  • Instance name and the new makespan.
  • The permutation (required), with job indices starting at 1. We re-evaluate it automatically, and a UB is never listed without a permutation that reproduces it.
  • A reference if one exists (paper, preprint, technical report or dataset DOI). Otherwise we credit the name and affiliation you give us.

Tip: run it through the solution checker first. If it beats the current UB, the checker prepares the email for you.

New lower bound or proof of optimality

  • Instance name and the new LB.
  • A citable document (paper, preprint or report) that describes the method and the computation, e.g. the bounding scheme, B&B statistics and run time. Logs or certificates are welcome.
  • LB = UB closes the instance, which will then be marked Closed.

Send it

Email with the subject [PFSP] New bound for <instance>. For several instances, attach a CSV with the columns instance, type, value, permutation, reference.

Open email draft

What happens next

  1. Automatic verification The permutation is evaluated against the instance data, and any mismatch is rejected.
  2. Review A maintainer checks the reference (for LBs, the method), usually within a few days.
  3. Publication The new bound appears in the tables and on the instance page with its source, and is recorded in the instance's bound history.
  4. Archiving Periodic data releases are archived with a DOI, so papers can cite the exact version they used.

Please note: bounds are attributed to the first public source we can verify. If you believe a bound is mis-attributed or a lower bound is wrong, please write to us. Corrections are as valuable as improvements.
